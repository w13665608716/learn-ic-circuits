# 由实践提炼的决策案例

这些例子展示判断方式；名称、周期、节点及参数不构成新电路的默认值。

| 情境 | 执行动作 | 避免的错误 |
|---|---|---|
| 用户只问非核心模块作用 | 用接口和一个时序场景说明；必要时追踪控制路径 | 立即逐晶体管讲解 |
| 输出时钟前有计数器 | 追踪计数器输出是否只是门控使能，再判断是否分频 | 看见计数器就称输出是分频时钟 |
| 用户不理解功能说明 | 换成“使能出现后，等待哪些条件，再发生什么”的具体例子 | 重复抽象术语 |
| 核心单元由晶体管构成 | 先选择传输/保持/控制等关键机制 | 把所有器件编号讲一遍 |
| 用户已解释“传输门关闭，反馈保持” | 推进下一个未理解点 | 强制再查看直观内部波形 |
| 用户只做反馈二分频实验 | 记录该实验结果，独立采样/异步控制验证标跳过 | 宣称所有功能已分别验证 |
| 用户认为尺寸实验不需要 | 保留尺寸权衡理解，直接收尾 | 再次要求改大改小并仿真 |
| 用户说某 corner 出现多余脉冲，问题先 pass | 保留症状与未决状态，继续其他内容 | 将 pass 当功能通过或断言唯一根因 |
| 用户报告某目标频率跑通 | 给带条件的通过结论 | 宣称已找到最大频率或全部 PVT 通过 |
| 用户要求学习卡片更精简 | 缩短晶体管卡片，保留因果、配置、原图与证据边界 | 删掉重要未知条件，或生成冗长逐管手册 |

实现格式参照 Agent Skills 官方规范：https://agentskills.io/specification 。核心文件保持短小，按需加载参考资料与模板；更新结构时重新验证。
